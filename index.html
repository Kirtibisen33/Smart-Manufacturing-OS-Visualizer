This interactive educational simulator demonstrates how Operating Systems algorithms manage manufacturing tasks in a smart factory. Sensors, robotic arms, inspection units, and conveyor belts compete for CPU time, shared storage, reusable resources, and memory.

Problem Statement

A modern smart manufacturing factory uses industrial sensors, robotic arms, conveyor belts, inspection cameras, and packaging machines. Different manufacturing processes compete for CPU processing time. Sensors continuously produce inspection data that must be consumed by processing workers. Multiple processes compete for shared resources such as robotic arms, inspection units, and conveyor controllers. Memory must be allocated efficiently to sensor data, inspection software, and production tasks. Poor CPU scheduling may delay production. Improper synchronization may cause race conditions. Unsafe resource allocation may result in deadlock risks. Inefficient memory allocation may lead to failed allocations and external fragmentation.

Objectives

  • Demonstrate CPU scheduling algorithms (FCFS, SJF, Round Robin) for manufacturing processes.
  • Demonstrate Producer-Consumer synchronization using bounded storage and conceptual semaphores.
  • Apply Banker's Algorithm to avoid unsafe resource allocation.
  • Demonstrate First Fit and Best Fit memory allocation.
  • Visualize algorithms, calculations, intermediate states, and results.
  • Compare algorithms and explain their advantages and limitations.

Synchronization Concepts

  • Mutex: protects shared storage from conflicting access (critical section).
  • Empty semaphore: counts available free slots; producer waits when storage is full.
  • Full semaphore: counts stored items; consumer waits when storage is empty.
  • Normal operation enforces these rules so the stored count never exceeds capacity or becomes negative.

Integration of the Four Concepts

All four simulations use the same smart manufacturing scenario:

  • CPU Scheduling determines which manufacturing task uses the CPU.
  • Producer-Consumer Synchronization manages sensor data in shared bounded storage.
  • Banker's Algorithm evaluates whether resource allocation can remain in a safe state.
  • Memory Management allocates available memory to manufacturing tasks.

These are separate educational simulations in one browser application. They do not form a production-ready real-time operating system.

About, Limitations, and Learning Outcomes

Limitations

  • Single-threaded browser simulation; no real OS threads or semaphores.
  • Banker's Algorithm uses a fixed 5-process, 3-resource example (editable).
  • Memory model uses variable partitions with splitting; no compaction or paging.
  • No persistent storage or backend.

Learning Outcomes

  • Understand CPU scheduling metrics and trade-offs.
  • Understand bounded buffers, critical sections, mutex, and semaphores conceptually.
  • Understand deadlock avoidance and safe states.
  • Understand First Fit vs Best Fit and external fragmentation.
